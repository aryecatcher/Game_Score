# MVP 缺口审计

本清单依据 GameChanger 独立项目的 Notion 01–04 模块整理。它只描述当前 GameChanger 项目，不引用、复用或修改 Amadeus。

## 发布前必须冻结（P0 Gate）

1. **首发司法辖区**：国家/州、运营法律实体、隐私政策、儿童与监护人同意策略、数据驻留与删除时限。
2. **OfficialStatSet v1**：由公司教练签字确认事件词典、合法转换、统计公式、纠错规则和 GoldenGame 期望结果。
3. **身份与邀请**：OIDC 供应商、邮件/短信邀请通道、账号恢复、MFA/高风险操作再认证策略。
4. **视频供应商**：AWS IVS 或 Mux；推流 SDK、播放签名、录像、Webhook 签名和成本上限需要实测。
5. **iOS 发布参数**：Bundle ID、Apple Team ID、最低 iOS 版本、相机/麦克风/通知文案和所需 entitlement。
6. **商业占位值**：免费视频分钟数、PilotGrant 规则、个人订阅展示价格。P0 不创建可购买 StoreKit 商品。
7. **试点容量**：球队数、同时比赛数、每场并发观看数；压测门槛为约定峰值的 5 倍。

## 现有文档中容易漏掉的实现细节

- 比赛终场后的“重开”必须是受审计的高权限动作，不能由普通记分接口隐式完成。
- scorer authority 交接必须使用单调递增 `authority_epoch`；旧设备事件进入隔离队列而不是静默丢弃。
- 相同 `client_event_id` 但内容不同属于冲突，不应当当作成功重试。
- 实时消息必须包含逐场序号；发现缺口时客户端回退到 snapshot/events API 补洞。
- 播放授权、成员资格和同意撤回必须在短时间内生效，不能仅依赖长 TTL CDN URL。
- 视频 Webhook 必须验签、幂等并容忍乱序；录像状态不得依赖单次回调。
- 额度不能只存“剩余值”，应使用 append-only ledger/reservation，避免并发超发。
- 合成测试数据禁止包含真实未成年人姓名、生日、联系方式和视频。
- 删除请求要同时覆盖主库、对象存储、搜索/缓存、备份过期策略和审计证明。
- 需要定义时区、比赛计划变更、雨停/取消、统计纠错窗口、客服下架 SLA。

## 当前代码的处理方式

- 默认 `APP_MODE=memory`，只加载固定合成数据。
- 所有未冻结项通过环境变量、策略配置或 Provider 端口隔离。
- 生产数据适配器不会因启动开发服务而被隐式选择。
- `ACCOUNT_MIN_AGE` 留空的含义是“尚未完成司法辖区判断”，不是允许儿童自由注册。
